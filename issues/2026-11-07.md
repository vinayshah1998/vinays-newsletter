## Computer use comes home

### [agent-desktop: computer use for any coding agent](https://x.com/ctatedev/status/2116323148706771302)
**Chris Tate (@ctatedev)** · *product launch (video)*

Chris Tate introduces [agent-desktop](https://x.com/ctatedev/status/2116323148706771302): "agent-browser, for your whole computer." Computer use for any coding agent, on macOS, Windows, and Linux. It runs in the background while you keep working, and agents can use the computer in parallel, each with its own cursor.

**Why it matters:** This is the missing layer between a coding agent that edits files and one that can actually operate the machine your product lives on. Worth watching for how Cursor/Claude/Amp-style agents will want to ship demos without a human babysitting the mouse.

### [terminal-mac: an entire macOS inside your terminal](https://x.com/kirtandopamine/status/2117678349828976746)
**Kirtan (@kirtandopamine)** · *open-source launch (video)*

Kirtan ships terminal-mac: "Entire MacOS that runs inside your existing terminal." Pitch: give your agent its own Mac and keep yours; watch it work live next to your terminal; computer use built in via MCP, CLI, and skill. Free and open source.

**Why it matters:** Same idea as agent-desktop, different packaging: isolate the agent's machine so it can thrash a VM while you keep your host. Useful pattern for a coding-agent product that needs sandboxed computer use.

### [Exploring Super-agent Design](https://x.com/DeepSeekHarness/status/2116857257245987236)
**DeepSeek Harness (@DeepSeekHarness)** · *X Article (architecture essay)*

DeepSeek Harness posts a long architecture essay (machine-translated from Chinese) arguing that single-session ReAct agents can't support always-online, multi-task work. They call the alternative a "Super-agent" with four traits: Continuous (one identity across IM and GitHub), Productive (parallel tasks, take the next instruction before the last finishes), Proactive (monitor events, act without being @-mentioned), and Persistent (always online, recover from anomalies). Their internal instance continues a development task across IM and GitHub and opens PRs from public group-chat feedback without being pinged. They note a person can usually follow only 3–5 active sessions, so multi-tasking is bottlenecked by human attention, not the model.

**Why it matters:** This is the product brief for what you're building, written as an architecture note: session isolation is the bug, not a feature. The four traits are a useful checklist against your own harness.

## Memory, UI, and the agent surface

### [The components of agent memory (and dreaming)](https://x.com/AnthropicAI/status/2118814753154064501)
**Anthropic (@AnthropicAI)** · *engineering blog post*

Anthropic's Engineering blog, [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory) (Nov 6). They treat agent memory as knowledge gained from experience and kept between sessions as readable notes—not weight updates, not in-context learning, not compaction. The key idea is "dreaming": offline compute between sessions that replays logs, corrects bad notes, builds wiki-style representations, and promotes a small header into the next session's injected context (Claude Code's auto memory loads only the first 200 lines / 25 KB of MEMORY.md). On Continual Learning Bench, stronger Claudes closed the loop themselves—writing rules plus how they knew the rules were true. On Pokémon, Sonnet 3.7 wrote 413 memory files and earned one badge; Fable 5 wrote nine files plus a global.md and earned four. Dreaming fixed a wrong Mt. Moon landmark note against the transcript and got Claude through the cave. On a ~350k-file Stainless corpus, scaling dreaming from 2 to 128 sessions raised a 25-question eval from 13% to 48% of graded criteria; wiki plus search beat search alone and saved ~20k tokens per question.

**Why it matters:** This is the memory design doc your coding agent will be measured against. Dreaming as a background job—correct, consolidate, inject a tiny header—is a concrete architecture, not a vibe.

### [Generative UI for conversational agents](https://x.com/rauchg/status/2118856239719608353)
**Guillermo Rauch (@rauchg)** · *Vercel changelog + video*

Guillermo Rauch announces that Chat SDK agents can stream generative UI with [json-render](https://vercel.com/changelog/json-render-and-chat-sdk-agents). Combine the AI SDK, Chat SDK, and json-render: the agent writes a typed JSON spec, adapters render native cards (Block Kit on Slack, Adaptive Cards on Teams). `streamCard` posts once the root has content and updates at most every 500 ms; `toCard` validates props and throws readable `CardSpecError`s the model can fix. He calls this the coming dominant Human-Agent Interaction paradigm.

**Why it matters:** If your agent lives in Slack (and yours does), streaming typed cards instead of walls of markdown is the interaction model to copy. The catalog-as-system-prompt pattern is also clean.

### [Weight-Space Programming: edit weights without training](https://x.com/rikiyatakehi/status/2117313742891327994)
**Rikiya Takehi (@rikiyatakehi)** · *research thread + blog*

Rikiya Takehi reports asking GPT-6 Astra to edit Qwen3.5-0.8B weights to improve math. It changed only 0.016% of weights, fixed reasoning loops, improved math up to 6× and instruction following 3×, without gradients or training. They call it Weight-Space Programming: frontier LLMs natively reading and writing neural network weights.

**Why it matters:** Even if you never ship this, "frontier model as weight editor" is a new primitive sitting next to fine-tuning. File it under things that rearrange the product roadmap.

### [Hex: local voice dictation](https://x.com/thdxr/status/2118067183406518551)
**dax (@thdxr)** · *product link*

dax links [Hex](https://anoma.ly/hex): local voice dictation for Mac, Windows, and Linux. Hold Option, say what you mean, and Hex pastes it where you are. Install via Homebrew cask, PowerShell, or a Linux script. In a related post he notes Hex hit 25,000 daily active users in five days.

**Why it matters:** lauren's Grok Bot tip was "use voice mode." Hex is the system-wide version—local, cross-platform, and suddenly very popular. Relevant if your agent onboarding starts with a brain dump.

### [Critical thinking when agents do the work](https://x.com/addyosmani/status/2117512471930167377)
**Addy Osmani (@addyosmani)** · *X Article*

Addy Osmani's article maps a spectrum: cognitive offloading (delegate but keep ownership) → deferral (the tool's output becomes your input) → cognitive surrender (the AI's output quietly becomes yours). He borrows "cognitive surrender" from Shaw and Nave at Wharton, and ties it to Storey's eroding shared system theory and his own "comprehension debt." Practices: once a week write code without an agent; once a month write down what you've stopped doing; have a hypothesis before you ask; read what it ran before the summary; if you wouldn't put your name on it, it doesn't ship. "You may offload the work and much of the auditing, but not the accountability."

**Why it matters:** The honest companion piece to every "agents write all the PRs" post. Bake "hypothesis before ask" and "read the evidence, not the summary" into your agent's review UX.

## Make the loop fast

### [How I made our CI 20× faster (steal this)](https://x.com/owengretzinger/status/2116331367407694118)
**owen (@owengretzinger)** · *X Article (quoted) + reaction video*

owen quote-posts his own article: at Boardy, PR CI went from up to 40 minutes to 2. "Every PR we ship is written with coding agents, and agents don't get tired of pushing… When writing code gets 10× faster and CI doesn't, CI is what you're waiting on." He treated CI like a product, mostly from an internal Slack agent on his phone. The checklist: leave GitHub's default runners (Blacksmith cut wait from 11 min to 8 sec); replace ESLint with Oxlint (2 min → 5 sec); chase faster typecheckers (tsc 70s → TS 7 at 13s → bun check under 5s; locally tsrs at 0.6s); shard tests onto bigger machines; set Vitest `isolate: false` (100s → 35s per shard, with a reset hook); fix setup and cache seeding from main (a year-old bug where half of PR runs missed cache); run lint/typecheck/build/tests in parallel; use nx affected; put format/lint/typecheck in a pre-push hook ("agents skip steps" in AGENTS.md). CI bill: $230/mo → $4,300/mo, "the cheapest money we spend on making agents faster." Next bottleneck: him clicking merge.

**Why it matters:** This is the agent-loop bottleneck written as a runbook. Hand the article to your agent and point it at your own CI. The pre-push-hook-not-AGENTS.md line is the one to steal first.

### [What Jarred says to Claude during perf work](https://x.com/jarredsumner/status/2117037940031496252)
**Jarred Sumner (@jarredsumner)** · *prompt list*

**Why it matters:** Paste-ready prompts with a point of view. "Caching is cope" belongs in your agent's perf skill.

### [More hot-path prompts from Dylan](https://x.com/_dylanga/status/2117400205314421058)
**Dylan Garcia (@_dylanga)** · *prompt list (quote-post)*

Dylan Garcia continues a thread of "bangers for healthy systems, fast software, and happy users": select only the fields you need instead of loading whole rows; remove unnecessary `new URL()` parsing; compute regexes at module level, not inside functions/loops; promote hot-path keys out of large jsonb columns into real columns. On that last one: "we had queries that had to detoast 20gb+ of data just to need a couple of kb."

**Why it matters:** Concrete, reviewable diffs. Pair with Jarred's list as a weekly "ask the agent to hunt these" chore.

### [Observability prompts that actually stick](https://x.com/_dylanga/status/2117756672202436674)
**Dylan Garcia (@_dylanga)** · *prompt list*

Dylan on how you know you have healthy systems: observability. One prompt wires OpenTelemetry tracing across a Hono repo—trace at function definitions, lint-rule the behavior, attach request context to every span, propagate traceparents. Another: read Boris Tane's piece and implement it everywhere. "If you don't know what's happening in production, your p0 is doing that."

**Why it matters:** Agents are great at the mechanical part of instrumentation and terrible at deciding to start. Make this a default skill on any underobserved service.

### [You can't bullshit 500k req/s: Google's NALSD](https://x.com/kayleecodez/status/2118442156008571274)
**mitali (@kayleecodez)** · *link to Google SRE workbook*

mitali: "you can bullshit your way through a system design diagram but unfortunately you cannot bullshit your way through 500k req/s." Links Google's SRE workbook chapter on [Non-Abstract Large System Design](https://sre.google/workbook/non-abstract-design): iterate a design with real resource estimates (machines, IOPS, network), asking is it possible / can we do better / is it feasible / is it resilient. **Why it matters:** NALSD is the antidote to agent-generated architecture diagrams that never meet a disk. Good homework for any system-design skill you give your agent.

## Weekend hacks, markets, and life

### [Karpathy's weekend hack: HackerTube](https://x.com/karpathy/status/2116957135661945283)
**Andrej Karpathy (@karpathy)** · *weekend project*

Karpathy was annoyed with YouTube recommendations, so he had Claude filter 43 million comments over 20 years of HN down to 6,454 videos that keep getting recommended. Result: [hackertube.org](https://hackertube.org/), ~2 hours with Opus 5.5. No login (state in local browser session); thumbnails are a mid-video frame instead of A/B-optimized uploads; underlying data ships as a zip so you can point your own Claude at it. He only did three manual things (YouTube API key, VPS, domain); Claude secured, hardened, deployed, and optimized the rest. "Many awesome projects that would have normally taken weeks/months even can now be few-shotted for breakfast."

**Why it matters:** The canonical "what else are we not thinking of" post. Also a reminder that the interesting product might be the filtered corpus, not the model.

### [Hedge fund hotels and why being right stopped paying](https://x.com/huaxying/status/2118427336580419774)
**Hua (@huaxying)** · *long market essay*

Hua's essay on how the fundamental HF game broke. Alt data used to be an edge; then everyone got the same datasets and the same read on the quarter. The players changed: ETFs, pods with identical risk constraints, long-onlys rotating out of value, retail. Names became "hedge fund hotels"—everyone knew the company, obsessed over the same line items, and when you were right there was nobody left to follow the trade. Now the AI trade has everyone checked into the same hotel. Pods move first on the unwind because leverage and tight drawdowns can't sit through a −2%. Closing question: can AI help spot the break, or does it just make everyone better at finding the same trade?

**Why it matters:** A clean explanation of crowded trades that maps uncomfortably well onto AI-assisted alpha in software too. Same tools, same reads, thinner edge.
