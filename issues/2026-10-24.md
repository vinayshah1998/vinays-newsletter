## Harnesses, durability, and runtimes

### [What is a "harness"?](https://x.com/theo/status/2113424203345265053)
**Theo - t3.gg (@theo)** · *X Article (explainer)*

Theo got tired of explaining it, so he wrote it down. A model only emits text. The harness is everything that turns that text into action: the tools (`read_file`, `edit_file`, `bash`, search), the call syntax, the parser that spots a call and runs it, the path that feeds results back, and the tool list with descriptions. He separates the *interface* (Claude Code's TUI, the Codex app) from the harness underneath (Anthropic Agent SDK, Codex App Server), and notes that harnesses get reused: Pi powers OpenClaw, and the Agent SDK and Codex App Server power T3 Code.

**Why it matters:** This is the glossary entry to send teammates before a design review of your coding agent. The interface/harness split is also a useful line to draw in your own architecture docs.

### [durable-harness: make any agent harness crash-proof](https://x.com/vercel/status/2112653833382027729)
**Vercel (@vercel)** · *open-source package + engineering blog post*

Vercel's [blog post](https://vercel.com/blog/making-every-harness-durable) explains the trick. Before every model or tool call, the harness writes an *intent* to a durable log. When the call finishes, it writes the *outcome*. A queue message backs up each turn, so if the function dies, a new one reads the log and carries on. Finished model calls are never re-billed. Tools declare `replay: 'safe'` (lookups) or `'never'` (refunds, PR comments), and a "never" tool that got interrupted goes back to the model as "possibly ran." It has adapters for Pi, OpenCode, Codex, and Claude Code, and it can self-host on Postgres with two environment variables.

**Why it matters:** The safe/never replay flag is the clearest answer yet to "what happens to side effects when the agent crashes mid-turn," and you will have to answer that for your product either way.

### [fx0: a fast, durable HTML artifact builder on libfx](https://x.com/rauchg/status/2112247046082363821)
**Guillermo Rauch (@rauchg)** · *open-source demo app*

Guillermo Rauch says building the low-level plumbing that lets v0 survive server crashes, flaky LLMs, and function limits "was a huge pain," and libfx is that plumbing, now open source. The demo, [fx0](https://fx0.vercel.dev), is a design agent that turns a chat into one HTML file. Each chat is a libfx session saved step by step, so if the function dies mid-reply, a new one picks up from the last step. The agent's instructions live in `lib/agent.ts` and its tools in `lib/tools.ts`.

**Why it matters:** It's a small, readable reference app for the same durability idea as the post above. It's easier to fork for a weekend than to read the full SDK.

### [Ultimate: a self-extending harness built on Pi Durable](https://x.com/DanielGri/status/2113544750972194852)
**Daniel Griesser (@DanielGri)** · *blog post (toy project)*

Daniel Griesser (Sentry) [writes up](https://danielgriesser.com/posts/ultimate/) a harness that rebuilds itself while it runs. A supervisor holds the port while a new process proves it can boot. Every feature gets its own worktree, test server, and browser-driven screenshots. A standing "lander" agent runs all the tests and resolves merge conflicts, and in one example it landed only after 407 tests passed. His favorite primitive is the *note*, a message that doesn't wake the receiving agent and just waits for its next turn. Running Ultimates find each other over Tailscale.

**Why it matters:** Notes versus messages, standing agents, and a lander that owns merging are all product ideas worth borrowing, and the Tailscale detail will feel familiar from your homelab.

### [Infinity: an agent runtime where scale to zero is the default](https://x.com/clare_liguori/status/2113752461295182182)
**Clare Liguori (@clare_liguori)** · *Rust framework launch*

Clare Liguori says @ShadajL announced it at AGNTCon. The [project site](https://infinity.hydro.run/) says that between turns an idle agent is pure data: no task, no stack, no open connection. After twenty tool-calling turns an agent takes about 103 KB, so roughly 75k of them fit in 8 GB, "the memory of a Raspberry Pi." On AWS Lambda, each SQS FIFO delivery runs one step of the runtime, and it ships CDK constructs. It also defines a Reactive Agent Protocol, where a tool call is a POST with a callback URL instead of a held-open connection.

**Why it matters:** It's Rust, it runs on Lambda, SQS, and CDK, and it treats waiting as free. That is very close to the stack you already know, aimed at the cost problem every coding agent has during a 20-minute CI run.

## Review, verification, and evals

### [Cloudflare cut its AI code reviewer's bill by 68%](https://x.com/Cloudflare/status/2112280767308918908)
**Cloudflare (@Cloudflare)** · *engineering blog post*

[The post](https://blog.cloudflare.com/obsessive-inference-optimization/) walks through it. Average review cost went from $1.19 in April to about $2.46 by August. Now it's $0.77, and the median review takes 1m 32s instead of 4m 09s. The biggest single fix: OpenCode v1 put the only cache breakpoint after a per-repository environment block, so the first request of a session hit the cache only 14–26% of the time. Splitting the prompt at a shared marker fixed that. Other wins included removing a tool sub-reviewers kept calling and getting rejected, reading files in parallel, skipping unchanged reviewers on re-reviews, and actually stopping canceled jobs (358 of 446 kept running). Model changes were tested with 50/50 randomized splits, and quality was checked by whether authors changed the flagged lines.

**Why it matters:** This is basically your résumé in one blog post: per-session telemetry, prompt-cache mechanics, and A/B splits on models and effort, with quality guardrails. See the pick of the week.

### [Cloudflare open-sources its security-audit skill](https://x.com/RoundtableSpace/status/2112125353594401162)
**0xMarioNawfal - The Roundtable Show (@RoundtableSpace)** · *agent skill (GitHub repo)*

It runs six phases: map the codebase, hunt area by area, send every finding to a *fresh* agent that didn't find it, write structured results, verify each record again, and report. Findings come out as confirmed, needs validation, or rejected. **Why it matters:** "A different agent confirms each finding" is a cheap way to cut false positives. Try it on one of your own repos before trusting any agent's security report.

### [Code review sucks now, but it doesn't have to](https://x.com/dillon_mulroy/status/2111929961947041849)
**Dillon Mulroy (@dillon_mulroy)** · *quote-post + blog post*

### [How to use decision models for evals](https://x.com/HamelHusain/status/2112588257104216294)
**Hamel Husain (@HamelHusain)** · *X Article / blog post*

Hamel Husain and Antaripa Saha test six "decision models" (Jev 1.13, Perplexity Decider, Liquid d1 and d1-ultra, Cloudflare Clef Flash, and OpenAI Decisions) on 100 labeled traces from an apartment-leasing agent. Their main point: don't trust the default 0.5 threshold. A model that scores every failure 0.40 and every pass 0.10 classifies perfectly at 0.30 and catches nothing at 0.5. The post covers tuning for precision and recall, cost, and calibration. The interactive charts are on hamel.dev.

**Why it matters:** Threshold tuning and calibration are home turf for an experimentation person, and cheap classifiers make good judges for agent trace evals.

**elvis (@omarsar0)** · *quote-post (reading list)*

### [On benchmarking](https://x.com/BenjDicken/status/2112251037587583410)
**Ben Dicken (@BenjDicken)** · *blog post (PlanetScale)*

Ben Dicken says "most of you need to read this," and he means [his own guide](https://planetscale.com/blog/on-benchmarking). The highlights: keep the client from becoming the bottleneck, match instance generations (r7g vs. r8g is about 15% in Geekbench), warm caches first, and choose open versus closed loop on purpose (closed loop hides coordinated omission). Report percentiles and variance, not just averages, and document everything. It closes with a list of "benchmark crimes."

**Why it matters:** It applies just as well to benchmarking agents and inference gateways. Coordinated omission especially will skew any latency number your agent product publishes.
